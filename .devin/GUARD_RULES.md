# Devin 隔离铁律（每个任务开工前必读并严格遵守）

> 本文件只约束 Devin。任务提示词开头会写「先读 .devin/GUARD_RULES.md 并严格遵守」。
> 违反任意一条 → 立刻停手，向用户报告，等指示。

## 1. 不全盘读文件（最小读取）

- 只读「任务提示词点名的文件」+ 它们直接依赖的少量文件。
- 禁止全仓库漫游、禁止批量读整个目录、禁止「为了解上下文」去翻无关文件。
- 需要某个未点名文件时：先说明为什么要读、读哪一个，再读。
- `signing/`、任何 keystore / 密钥 / 机密文件：禁读（已在 config.json 硬禁）。

## 2. 禁止推测（无证据不下结论）

- 只认两类证据：① 读到的真实代码 / 配置原文；② 跑出来的日志 / 命令输出原文。
- 没有上述证据，禁止写「应该 / 可能 / 估计 / 大概 / 推测」式结论。
- 拿不准 → 停手，向用户提一个具体问题，等回复。
- 修复必须先定位根因（先复现 / 先读到证据），禁止症状级瞎改；两次无效即停手复盘。

## 3. 命名规约（输出 / 注释 / commit 一律照此）

- 禁止出现任何产品品牌名。只能用代号：
  - 包名直接写：`com.tencent.mm`（官替线）/ `com.tencent.mn`（共存线）。
  - 形态写：官方包 / 原版 / 官替版 / 共存版 / 宿主包。
- 禁止写「注入」（指产品形态）→ 写「重新打包」。例外：技术正确词「底层注入三件套 / 注入 JNI 链 / hook 注入检测」照写。
- 禁止写「封号」全词 → 写「封」或「账号异常」。
- 「防破解 / 逆向 / 反编译」可直接写（我们是防守方）。
- 技术锚点照写：`签名` / `android_id` / `getPackageInfo` / `LSPatch` / `libguardcore.so` 等。

## 4. 提交规约（Devin 自己提交）

- 改完可自行 `git commit`（本地提交）。
- 禁止 `git push`（已在 config.json 硬禁）、禁止改 git config、禁止 force / reset --hard。
- commit message 遵守上面命名规约：不出现品牌名，用包名 / 官替 / 共存。
- 只提交本任务点名 / 实际改动的文件，禁止 `git add -A` 把无关改动裹进来。

## 5. 高风险写操作先确认

- 删文件 / 删大量代码 / 改密钥·证书 / 重生成 registry_cipher / 任何外部可见副作用：动手前先报告 + 等用户点头 + 先 git 快照。
