## 背景

当前 LSPosed 模块在 8.0.71 上 KPI 全绿（verifiedbootstate=0）。
但微信可能存在以下自校验逻辑，在封号潮或版本更新时激活：

1. **APK 签名验证** — 检查自身签名是否被替换（改包风险）
2. **DEX/SO 完整性校验** — 校验 classes.dex 或核心 .so 的哈希
3. **Hook 特征扫描** — 检查方法入口是否被 Xposed 替换（Matrix SDK）
4. **模块包名扫描** — 扫描已加载类/进程中是否有 `de.robv.android.xposed` 等特征

---

## 调研目标

找到上述校验代码的**调用位置**，评估当前模块的暴露面。

## 调研方法（Frida 动态）

### Step 1：定位签名读取

```javascript
// 监听 PackageManager.getPackageInfo 带签名 flag 的调用
Java.use("android.app.ApplicationPackageManager").getPackageInfo.overload(
    "java.lang.String", "int"
).implementation = function(pkg, flags) {
    if (flags & 0x40000000 || flags & 0x8000000) { // GET_SIGNATURES / GET_SIGNING_CERTIFICATES
        console.log("[SIG] getPackageInfo pkg=" + pkg + " flags=0x" + flags.toString(16));
        console.log(Java.use("android.util.Log").getStackTraceString(
            Java.use("java.lang.Exception").$new("stack")));
    }
    return this.getPackageInfo(pkg, flags);
};
```

### Step 2：定位文件哈希校验

```javascript
// 监听 MessageDigest（MD5/SHA）的 digest() 调用
Java.use("java.security.MessageDigest").digest.overload().implementation = function() {
    var result = this.digest();
    var algo = this.getAlgorithm();
    // 只打微信自己触发的（排除系统库）
    console.log("[HASH] algo=" + algo + " stack=...");
    return result;
};
```

### Step 3：定位 Xposed 特征扫描

```javascript
// 监听 ClassLoader.loadClass，看是否扫 xposed 包名
Java.use("java.lang.ClassLoader").loadClass.overload("java.lang.String").implementation = function(name) {
    if (name.indexOf("xposed") >= 0 || name.indexOf("lspatch") >= 0) {
        console.log("[XCHECK] loadClass: " + name);
    }
    return this.loadClass(name);
};
```
