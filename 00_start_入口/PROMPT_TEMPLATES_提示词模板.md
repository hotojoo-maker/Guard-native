# PROMPT_TEMPLATES — 提示词模板速查册

> **用法**：找到你的场景 → 复制提示词 → 粘到 Cursor / Claude Code 对话框 → 把 `<占位符>` 改成你的
> 5 个窗口（W1~W4 干活 + W5 总管） × 5 个 skill

---

## 一、5 窗口模板（W1~W4 通用，换变量即可）

### ① 早 — 接手当天任务

```
我是 W<N>（主题:<W1脚手架 | W2朋友圈 | W3会话 | W4离线采集>）的新会话。
任务: P<编号>_<主题>

请用 guard-dispatch_总调度 skill：
1. 读 CLAUDE.md / HOOKMAP.md / TASK_BOARD.md
2. 更新 TASK_BOARD.md §一 我的占用行
3. 给我一份当天接手报告（当前状态 / 下一步 3 条 / 风险）
```

变量：W1/W2/W3/W4 + P15/P16/P17/P18

---

### ② 中 — 进入干活模式

```
进入 P<编号> 实现 <模块名,如 StateMachine / MomentsFilter / ConvFilter>。

请用 guard-execute-one_单任务执行 skill：
1. 必读: CLAUDE.md §<对应章节>, HOOKMAP.md §<对应模块>, FAILURE_LOG.md 全部 34 条（F-01~F-34）
2. 进入 03_execute_执行任务/P<编号>_<主题>/ 目录
3. 按 result.md 模板开干，每完成一个子任务勾一项
4. 写代码禁用敏感词（vip/hide/pirate/wechat/catfish/myauth/wmiyou）
5. 类名/MMKV key 用 seed 化短哈希
```

---

### ③ 晚 — 收尾交接

```
W<N> 今天 P<编号> 完成了:
- <一行描述>

请用 guard-review_审稿复核 skill 自审：
1. 证据分级扫描（L1-L4 是否标注）
2. 自洽性（跨文件版本号 / 类名 / 字段一致）
3. 引用完整性（限定词是否丢失）
4. 跑 frida_stats.js spawn 对比基线（KPI 不增量）
5. 更新 HOOKMAP.md 对应行 ⬜→🟡 或 🟡→✅
6. 写 5-10 行交接快照到 04_review_审稿复核/W<N>_<日期>.md
7. 释放 TASK_BOARD.md §一 占用
```

## 二、W5 总管窗口（4 顶帽子轮换）

### ④ 总调度（早 8 点）

```
今天开工。请用 guard-dispatch_总调度 skill：
1. 看 TASK_BOARD.md §一 4 窗口占用情况
2. 检查昨天有没有遗留任务/冲突
3. 给出今日 4 窗口分工建议（哪个窗口先开 / 哪个等依赖）
4. 风险提示（如有阻塞）
```

---

### ⑤ 资料盘点（中午）— 资料员/文档员角色已并入 guard-review

```
请用 guard-review_质检门控 skill 的"资料功能"档：
1. 盘点 06_refs_参考资料/ 是否有新增没登记的资料
2. 检查 PROJECT_INDEX.md 路径是否还有效
3. grep 跨文件结论是否有冲突（同一类名/字段写法不同）
4. 看 04_review_审稿复核/T_TASKS/ 还有哪些 T 任务待派
5. 给出资料盘点报告
```

---

### ⑥ 审稿（傍晚审 W1~W4 产出）

```
请用 guard-review_审稿复核 skill 审稿 W<N> 今天的产出：
- 文件: <文件路径,可多个>
- 重点: <要审什么,如"证据分级是否标到 L1"/"路径是否真实"/"引用是否丢限定词">

输出: 通过 / 有条件通过 / 退回重写
```

---

### ⑦ 风险门控（发版前 / 进主线前）

```
v<N> 准备<进主线 | 发版 | 改 APK>。

请用 guard-risk-check_风险复核 skill 跑 5 项检查：
1. 污染源检查（撤回结论是否还在引用）
2. 证据升格检查（L3/L4 升 L1 是否有出处）
3. 二进制改动授权检查（APK/SO/DEX/MMKV 改动是否有用户授权记录）
4. 重复脚本/markdown 清理
5. 防检测 KPI 红线：跑 frida_stats.js 30 分钟对比基线

输出: 通过 / 有条件通过(列补充项) / 阻塞(列必修项)
```

## 三、3 个特殊场景

### ⑧ 死循环求救（写代码卡了 > 30 分钟）

```
我在 P<编号> 卡住了:
- 现象: <一句话症状>
- 尝试过: <方案 A 失败 / 方案 B 失败>
- 报错日志: <粘 10 行>

请：
1. 先 grep FAILURE_LOG.md 看是不是 34 条 F-XX 失败档案之一
2. 看 docs/HOOK_MAP_8071_AUTHORITATIVE.md（8071）；历史见 docs/archive/INDEX.md
3. 看 refs/MainEntry.java 看 Catfish 怎么做的
4. 如以上都不行 → 派 T 调研任务到 04_review_审稿复核/T_TASKS/

不要建议尝试 FAILURE_LOG 已禁的方案。
```

---

### ⑨ 跨窗口同步（W5 协调 W2 + W3）

```
请用 guard-dispatch_总调度 skill 做跨窗口同步：
- W2 状态: <一句话>
- W3 状态: <一句话>
- 冲突点: <如"两边都要改 HOOKMAP.md §D"/"W3 依赖 W2 的 wxid 提取链路">

输出:
1. 谁先谁后
2. 共享数据放哪（06_refs_参考资料/<子目录>）
3. 更新 TASK_BOARD.md §三 依赖关系
```

---

### ⑩ 派 T 调研任务（便宜模型独立完成）

```
请用 guard-review_质检门控 skill 的"资料功能"档派出新 T 调研任务:
- 主题: <如"8.0.66 ContactInfo Proto 类定位">
- 派出窗口: <W2 / W3 / W5>
- 模型建议: Haiku
- 输入: <文件/数据路径>
- 任务: <1-3 个具体动作>
- 产出格式: <期望文件/字段>
- 验收: <通过判据>

写到 04_review_审稿复核/T_TASKS/T<编号>_<主题>.md
```

## 四、新会话最简化提示词（懒人版）

如果你嫌上面太长，**只复制这一段**就能开工：

```
我是 Guard Native 项目的 W<N> 窗口（P<编号>_<主题>）。
请按 .cursor/skills/ 的 5 个 skill 规范工作。
今天的任务: <一句话>。

先读 CLAUDE.md，再领任务，干完自审。
```

---

## 五、提示词使用铁律

1. **永远先告诉 AI 你是哪个窗口**（W1~W5）
2. **永远说 P 任务编号**（避免 AI 误判任务范围）
3. **永远引用 FAILURE_LOG**（防止 AI 重蹈覆辙）
4. **永远要求自审**（每个子任务完成后）
5. **不要让 AI 跨窗口工作**（一个会话只干一个 P 任务）
