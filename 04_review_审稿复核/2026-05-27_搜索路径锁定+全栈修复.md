## 六、教训与原则

### 教训

1. **资料权威性 > 推断**——`03_执行任务/P20_搜索拦截/scripts/fts_view_probe5.js` 早就 hook 了 f0，没读就开干 → 浪费 1 小时。
2. **f0.getView 是死路**——q2 是 ListView Adapter 但 ListView GONE → 强制接口 getView 也不触发。
3. **真渲染层是 ss4.p**——FTSMainUI 用 RecyclerView 不是 ListView，跟设置页 `pz3.g` 同源（WxRecyclerView 系列）。
4. **install 链漏调静默失败**——ContactLabelHideGuard / SelfProfileCapture 被某次"顺手优化"漏掉 install 调用，代码躺仓库不工作。typeof "F-31 D1 h1() 静默失效"。
5. **README 误判会污染下游**——dynamic_crawler README v1.1 写 `fz2.e g=SOSItemRelevant:wxid`，实测是 UIN 数字，导致整个 SearchFilter 设计走偏。

### 新原则

| # | 原则 | 触发条件 |
|:-:|------|------|
| 1 | **动手写 hook 前必跑两步 grep** | (a) src + docs (b) `tools/` + `03_execute_执行任务/*/scripts/` |
| 2 | **不要预先优化，先看 UI 实际效果** | View.GONE 铁律警告 vs Catfish hookFts 已实证可行 |
| 3 | **install 链改动前必扫漏**：每个 `Xxx.install` 文件存在但 ModuleMain 没调用 → 补 | 类似 F-31 静默失效 |
| 4 | **跨版本类名禁直搬**：8.0.66 / 8.0.70 / 8.0.71 各一套 | docs/HOOK_MAP_8071_AUTHORITATIVE.md §零 |
| 5 | **文档污染必先纠偏**：发现误判立刻更新所有引用此误判的文档 | dynamic_crawler README / HOOKMAP / HOOK_MAP_8071_AUTHORITATIVE |
