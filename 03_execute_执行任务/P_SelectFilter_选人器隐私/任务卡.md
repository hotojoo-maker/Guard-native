## 一句话

隐藏态时，发朋友圈「谁可以看 / 不给谁看」的选人器（选择朋友 / 选择标签 / 从群聊导入）**自动过滤密友 + 密群**，杜绝隐私暴露。门控复用 `StateMachine.isActive()`——**显形态加密友不受影响**（加密友必在显形态，`isActive()=false` 自动不过滤，不冲突）。

## 实现方案（jadx 裁定：方案 C + 构造前挂点）

- **C（推荐 · 最优挂点）** hook **`SnsAddressUI.G7()`@after 或 `w7()`@before** —— 在 adapter 构造前把 `Bridge.allHiddenIds()` addAll 进 `this.D`（= 传给 h0 的 a5.m 排除名单），**适配器构造器首次 `s()` 就排除掉**，无需手动重查、绕开未反编译的 s() 黑盒。门控 `isActive()`；加密友不受影响（不同 Activity / `isActive()=false`）。
- **B（备选）** 包装 `h0.z` MergeCursor，按 `z3.c1()` 过滤 row — CursorWrapper 重映射 position，复杂。
- **A（弃）** hook getItem/getCount — index 错位 + 高频，近 F-14。

代码骨架（方案 C）：

```
moduleD/SelectContactFilter.java（新建）
hook SnsAddressUI.G7()@after（或 w7()@before · 待设备确认实际 Activity）:
  if (!StateMachine.getInstance().isActive()) return;   // 显形态不过滤（加密友不受影响）
  反射 this.D（= 传给 h0 构造的 a5.m 排除名单 List）
  this.D.addAll(Bridge.getInstance().allHiddenIds());   // 密友 ∪ 密群 → 构造器首次 s() 即排除
ModuleMain 注册 SelectContactFilter.install（app classloader）
```

> wxid 提取（若改走方案 B）：`item.u` → 字段 `a.A`(z3) → `z3.c1()`，与 `ContactFilter` 同。
> 落码前过**授权检查官**（新增 Filter 链，只读 `isActive()`，不碰状态机/授权）。
