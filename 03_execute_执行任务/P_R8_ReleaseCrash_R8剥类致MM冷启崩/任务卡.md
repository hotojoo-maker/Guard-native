# P_R8_ReleaseCrash · Release 版 R8 剥类致 mm 冷启崩

> 立项：2026-07-01（架构师 FAST-K99；F.4 装机验证时暴露）
> 优先级：高（阻塞任何 official release 出包 → 阻塞真机验证 + 正式发版）
> 关联：`03_execute_执行任务/P_VersionKill_版本停用/设计稿_版本停用VersionKill.md` · `_CORE_现状真源/授权_当前真源.md §⑥`

## 症状

`.\tools\lspatch_pack.ps1 -Flavor official -BuildType release -Clean -Build` 打出的官替 LSPatched APK 装机后，`com.tencent.mm` 冷启秒崩：

```
LSPAppComponentFactoryStub.<clinit>
  → ExceptionInInitializerError
  → Caused by: java.lang.NoClassDefFoundError:
     Class not found using the boot class loader; no stack trace available
```

- 主进程直接崩（`<clinit>` 阶段），进不到 heartbeat / activate 代码。
- 共存 `com.tencent.mn` 未升级同版，仍旧 mod 能用；之前版本不报 = R8 优化随代码变化难预测。
- 现状：手机官替 mm 处于崩溃态；用户无历史 LSPatched v1.6 备份，恢复必修此 crash。

## 根因方向（L4 待验）

Release 变体走 R8（`minifyEnabled true`）+ 混淆/tree-shaking，剥掉了 `LSPAppComponentFactoryStub.<clinit>` 依赖的类。常见诱因：

- `LSPAppComponentFactoryStub` 反射引用类未加 keep
- 静态初始化链里通过反射/字符串名加载的类被 R8 判为死代码
- LSPatch 打包后新增的 `com.ghost.assist` 类被 R8 二次处理

## 待做

1. 拉完整崩栈（`adb logcat -b crash` 或 `-b main | Select-String "AndroidRuntime|FATAL"`），确认 `NoClassDefFoundError` 报的**具体缺失类名**。
2. 拉 `build/outputs/mapping/officialRelease/mapping.txt`，反查 R8 剥了哪些 `com.ghost.assist.*` / LSPatch stub 相关类。
3. 补 `proguard-rules.pro` 的 `-keep` 规则（LSPatch stub / 模块 static init 依赖链）。
4. 重出 release → LSPatch 打包 → 装机冷启动应活。
5. 加自动化 smoke（可选）：`.\tools\lspatch_pack.ps1 ... -Release` 后跑 monkey 30 秒无 FATAL。
