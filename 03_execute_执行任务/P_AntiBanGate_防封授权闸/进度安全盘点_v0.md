## 3. 风险 / 缺口（防封安全角度）

### 3.1 五条雷区（配方卡 §D，测不过就停）
| # | 雷区 | 安全后果 | 处置 |
|---|---|---|---|
| **D1** | **android_id 同源** | A2 android_id hook 若不限定仅微信 caller，会把我方 `computeDeviceHash` 读的 ANDROID_ID **一并 spoof 成官方 SSAID** → 全机 device hash 塌成同一值 → envelope `d` 设备绑定全废、永久标签/防共享/防转卖/不续命全失效 | A2 接主线时同步把 android_id hook **scope 限定仅微信 caller**、放过 computeDeviceHash（S6）；两机硬测 `d` 仍各异 |
| **D2** | 撤明文顺序 | 没验活就撤 Java 明文 → 正版机解密抖动时**密友暴露** | 先 registry+getRecipe 验活（entries=N、recipes ok、隐私四链绿）再撤明文 |
| **D3** | native 最小化 | 注入微信 JNI → CodecLooper SIGSEGV + 强制下线（铁律#23/F-23） | 仅自有 SO，不 dlopen 微信 SO、不注入微信 JNI |
| **D4** | 不改已验证 hook | 顺手优化已 PASS hook → 静默失效无报错（铁律#29/F-31） | 隐私四链 + 来电/通知回归仍绿 |
| **D5** | fail-closed | 解不开回退明文 / release 留明文 fallback → 逆向直抄配方绕过 SO 链 | 无 server seed → registry scatter → 敏感 hook 不装；解不开=散沙 |

### 3.2 落码前必须共审的 4 个真锁件（worklog 待办 + D-017）
- `GuardRuntime`：新增 `isAntiBanReady()`，**唯一 auth-aware 出口**。
- `EnvelopeStore`：`isAuthorizedNow()` = Ed25519 + device（P0 硬化）。
- `LeaseClock`：`trustedNow` 防回拨（24/72/144h 离线阶梯）。
- `Bridge`：新增「首装时间」键（用 4 字符短哈希）。

**2 watch（必须写进实现）**：
1. `isAntiBanReady` 时间线用 **`trustedNow - 首装时间` 自算**，**禁**复用 `LeaseClock.currentLevel()` 的 24/72/144h 离线阶梯（否则防封闸与隐私离线门**连坐**）。
2. **A2 料只进 `registry_pack`**，禁新增 `a2_pack`（配方收敛：4 pack + 一个 GuardRuntime 出口）。

### 3.3 安全官补充风险（从真锁视角，非配方卡原列）
- **真锁的牙仍在 Java（L2/隐患）**：`nativeIsAuthorized()` 永远 AUTH_OK 占位、Ed25519 验签在 Java → 可被 Frida hook。现 `isVipAuthorized` 虽接 EnvelopeStore，但**根锁的牙（验签）下沉 SO 要等 S8**；在此之前对外口径只能是「本地加密链路」。
- **MD5 ≠ 真锁（配方卡 §G.5 已自承，复核同意）**：包名+打包 MD5 = 完整性/防错配指纹，防混乱/冒充，**非防破解真锁**；真锁仍是 server seed + 短租约 + 设备绑定。运行时 APK/dex 自校验属阶段⑤ P32 `SignatureGuard`，本方案**不加运行时代码**（要加须指挥单独审）。
- **时钟回拨接受 = 已知 trade-off（决策13）**：首装 1h/2h/24h 判定首刻靠墙钟兜底 → 联网拿到服务器时间前，**改机器时间可绕首装宽限计时**；LeaseClock 防回拨只在曾联网后生效。属固有缺口，需 S9 服务器时间尽早介入收紧（L3）。
- **反白嫖核心 UI 是空的**：登录砸门弹窗**无实现锚点**（现仅 FunnelPrompt 可关闭引流窗）→「硬挡白嫖」这一层目前只有设计。
- **载荷弹窗 canary 未落码**：删弹窗自反噬（稳定核心段 hash 掺进 A2 料 key 派生）是设计，未实现。
- **信任分/心跳频率不能宣称安全**：60% 是占位、P18 KPI 零点未建（F-22）；demo/配方卡提到的心跳「装机 1min 起步」**需过防封官 CONN 红线 0.5 复核再锁**（L4）。

### 3.4 文档口径风险（建议指挥/总调度知会，本文不擅改）
- **时间口径三版漂移（L2）**：`DESIGN.md` 正文 §2/§5 表仍写 **T_kill=72h**（C36），§4A 写 **1h/最多2h**（C72），而 `配方卡_SPEC_v1`/`params.json` 定 **24h**（C81，声明为新真源覆盖旧值）。配方卡是最新真源没问题，但 **DESIGN 正文旧值未同步**，后人直读 DESIGN 易误用 72h/2h。建议（待指挥同意）：在 DESIGN 旧值处加「已被配方卡 C81 覆盖」显著标注，避免 G2 矛盾。
