## 0. 一句话

官替/共存是**两条独立发行线、同一套签名/工具/服务器**；差异只在 **宿主包名 + 由包名派生的一切**（native 期望包名、发行线 release_id、LSPatch 宿主、数据目录、资源）。**签名证书、device_id、A2 签名料三者两版相同**；A2 三轴里，签名 + android_id 两版都要照顾，包名/路径主要是共存版额外轴（详 SSOT §1.1）。

### 1.1 共存包名不要全局替换

| 用途 | 官替版 | 共存版 | 规则 |
|---|---|---|---|
| 运行目标 / LSPosed scope / 进程角色 / 数据目录 | `com.tencent.mm` | `com.tencent.mn` | 用真实宿主包名，不能拿官方包名硬套共存运行环境。 |
| `BuildConfig.GUARD_WX_PKG` / C++ `GUARD_EXPECTED_PACKAGE` | `com.tencent.mm` | `com.tencent.mn` | 编译期按 flavor 注入，禁止手工把全仓 `.mm` 改成 `.mn`。 |
| A2 喂给检测咽喉的身份输入 | 官方值 | 官方值 | 共存被 `c$p`/`normsg`/`bu5` 查自身时，选择性返回官方包名 / 官方路径 / 官方 DER，让检测输入尽量正常。 |
| 签名一致性覆盖 | `signatures[]` + `signingInfo` 都喂官方 DER | `signatures[]` + `signingInfo` 都喂官方 DER | 两条读取路径必须一起覆盖；只改 `signatures[]` 会漏 `bu5.a.a` 的 `GET_SIGNING_CERTIFICATES` 路径。 |

一句话：**真实运行身份按发行线走；检测喂料按官方态走。**不要用全局字符串替换解决共存。

## 3. 同源铁律（发版时官替/共存必须一起对齐 · 真源 = RELEASE_RULES）

> 详细流程不在此复写（G10），见 `docs/RELEASE_RULES.md`「双版本发布手册」+「s_rel 轮换 + 双版本 LSPatch 发版工作流」。本页只列「哪些必须两版同源」：

- Java 宿主白名单 / Xposed scope ← `BuildConfig.GUARD_WX_PKG`（已分 official/coexist）。
- C++ `GUARD_EXPECTED_PACKAGE` ← `-DGUARD_WX_PKG`（已分）。
- `release_id` + 服务器 `release_line` ← **缺口①待修**（当前未分）。
- `registry_cipher.inc` ← 同 keystore 故 cert 绑定一致；换 `s_rel` 时两版各自重生成、各自 `recipeOk=true` 装机回归。
- 冷启动验收（共存尤其看 `role=1 MAIN` 正确，呼应 §1 #2 坑）：`available=true` / `certBind=<证书前缀>` / `BATCH1_VERIFY PASS` / `role=1 MAIN`。

## 4. 与 A2/D-020 的关系（共存如何让数据正常）

- A2 防封闸口径以 **SSOT §2/§3（D-020）** 为准：本地 cert 完整性 + 时间闸，fail-open；**官替、共存同一套**（同 keystore → 同 `EXPECTED_CERT`）。
- 共存包（`com.tencent.mn`）被官方 `c$p` 自检时，A2 对检测 caller 灌官方态：签名 → 官方 DER；android_id → 官方签名对应 SSAID / 官方态；包名/路径 → 官方包名/路径。目标只写**让数据尽量正常**，不预测官方判分。
- 官替版已占官方包名，通常不需要包名/路径轴；但重签导致签名和 SSAID 仍会偏，所以签名 + android_id 两版都要照顾。
- 重签任一版 → `isIntegrityIntact=false` → 该版 A2 散沙（两版机制一致）。
