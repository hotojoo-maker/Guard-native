## 0. 终点（这条线要交付什么）

能**安全发版的「官替版 + 共存版」包**，三件齐：

1. **让数据正常**（A2）—— 在官方身份咽喉喂官方态/正常态，首装/断网/未授权窗口内尽量让数据读起来正常
2. **反盗版反白嫖闭环** —— 蜜罐绊线→影子期→散沙+引流，重签拿不到隐私
3. **服务器授权可控** —— 卡密/信封/一机一密/一键停用某版本，后台说了算

---

## 1. 核心打法（贯穿全表，铁定）

**借官方的眼睛、骑官方脖子**：

- `env`（`ro.boot.*` 等）由**官方自己读**，我方**零读取**（守铁律5 + KPI 硬约束，第三方读 → `verifiedbootstate` 计数 +1 自伤）。
- **root 不硬查**（不扫 su/magisk、不读 boot 属性）；root 至多**服务器侧软信号**，**付费即正版**。
- A2 在 `getPackageInfo` / `c$p` 咽喉**灌官方 DER**（`A2SignatureSpoof.OFFICIAL_DER_HEX`）→ 官方自检"是官方"→ 号不被判异常。

## 2. 两闸（A2 闸 = cert + 授权时效；隐私闸 = 授权）

| 闸 | 出口 | 吊什么 | 惠及谁 |
|---|---|---|---|
| **A2 防封闸** | `GuardRuntime.isAntiBanReady` | 本地 cert 完整性 **+ 时间闸**（首装 72h / 自然到期 7 天 / 封停删卡 72h；D-021）；cert 确证不符、或超窗仍未授权才散；读不到/相符/窗口内/异常=装(fail-open) | 未重签副本：**首装 72h 内 / 自然到期 7 天内 / 封停删卡 72h 内 / 断网 都尽量让数据正常**；超窗未授权 → 散沙 |
| **隐私闸** | `StateMachine.isActive()` 四层 AND | ① `isVipAuthorized`(=`EnvelopeStore.isAuthorizedNow`：token+Ed25519+license) ② `isSensitiveConfigReady`(registry server-seed) ③ `f1` 总开关 ④ HIDDEN 态 | 付费授权用户 |

- **A2 闸也吊时间闸**（推翻"未授权永久让数据正常"）：首装 72h 内装 A2(护首装)、**超 72h 仍未授权 → 撤 A2**；曾授权**自然到期/失效 → 宽限 7 天 → 撤 A2**；**服务器封停/删卡 → 宽限 72h → 撤 A2**（复用首装 72h；D-021，见 §3）。隐私闸仍只吊授权（封停/到期**立刻关**·可逆·两闸独立）。
- **真防护边界 = registry / SO / envelope**：光 hook `isActive`/`isVipAuthorized` 改 true **没用** —— `isSensitiveConfigReady` 第 2 层封死（没合法 envelope，`getRecipe()` 出不来真 registry = hook 配方拿不到）。`isActive` 这个布尔被读/被 hook **不算破防**（红队唯一破防标准）。

## 3. 场景矩阵（权威 —— 照此实现）

| # | 场景 | 触发 | 系统行为 | A2 让数据正常 | 隐私 | 弹窗 |
|---|------|------|---------|:---:|:---:|------|
| 1 | 首装未授权(观望/白嫖) | `NO_LICENSE` | **首装 72h 内装 A2**(护首装、给激活时间)；**超 72h 仍未授权 → A2 散沙** | 72h内✅ / 超→❌散 | 关 | 引导付费 |
| 2 | 付费授权中 | 有效信封 | 正常 | ✅装 | 开 | 无 |
| 3 | **临近到期(前7天)** | license 剩 ≤7 天 | 续费提醒 **每天 1 次**(新功能) | ✅装 | 开 | 软·每天1次 |
| 4 | 自然到期 | license 过期 | A2 7 天宽限后撤；**隐私到期即关**(可逆·重授权回) | ✅装→7天后撤 | **立刻关** | 软文案 |
| 5 | **服务器封停(后台kill)** | 后台停某卡/某设备 | A2 **72h** 宽限后撤；**隐私 rf=1 即散**(软，客户友好) | ✅装→72h后撤 | **立刻散** | 软文案 |
| 6 | **封禁/删卡密** | 后台封禁/删该卡密 | A2 **72h** 宽限后撤；**隐私立刻散** | 72h后❌散 | **立刻散** | 软文案 |
| 7 | 篡改/重签(盗版) | cert不符 / canary改 | 蜜罐影子期 7 天→**散沙+引流(吓人)** | ❌散沙 | 散沙 | 吓人文案 |
| 8 | 断网(短) | 暂无心跳 | 宽限，不误杀 | ✅装 | 开 | 无 |
| 9 | 断网(长 >144h) | 久无心跳 | 离线引流(联网可恢复) | ✅装 | 受限 | 软文案 |
| 10 | root + 付费 | root 但有信封 | **认正版** | ✅装 | 开 | 无 |
| 11 | root + 未付费 | root 无信封 | 服务器侧软风险 → 蜜罐档 | ✅装 | 关 | — |

**反分析铁律**：固定短散沙(掐表反推触发点)= 给破解者送分。故：

- **正版相关**(到期 #4 / 封停 #5) = 给宽限 + 软失效（客户友好，不涉反分析）。
- **盗版/篡改**(#7) = 7 天影子期(改完当场一切正常)→ 不续命 → 悄悄发作（反分析）。
- **超窗未授权**(#1·72h) + **自然到期**(#4·7 天) + **封停/删卡**(#5#6·72h) = 非篡改但会撤 A2 的场景（都带宽限、软失效，不立刻、不掐表）。隐私层另算：封停/到期**立刻关**(可逆)。

## 4. 关键拍板（✅ 已钉死 / 🟡 待确认）

- ✅ **未授权也会撤 A2（带宽限，非立刻）**：首装超 72h → 撤；曾授权**自然到期/失效**超 **7 天** → 撤；**服务器封停/删卡**超 **72h** → 撤（D-021 细化，用户拍板 2026-06-28）。
- ✅ **封停/封禁/删卡密 = A2 72h 宽限 → 撤；隐私 rf=1 立刻散**（A2 软、隐私即关·两闸独立，D-021）。
- ✅ **篡改/盗版 = 7 天影子期 → 散沙+引流**；反分析(7天影子期)**只对盗版**。
- ✅ **root + 付费 = 认正版**；root 不硬查。
- ✅ **临到期前 7 天每天 1 次续费提醒弹窗 = 已实现**(E99 复核)：`SettingsEntry.showRenewReminderIfNeeded`(7天窗口 + 可信日去重)。⚠️ 它走自己的 AlertDialog、**未走** `RiskPromptController` → 撞安全官红线#9(单一弹窗源)；**现状保留 + 记「红线#9 待收口」债**，块D 收口时统一(E99 架构师拍)。
- ✅ **封停/删卡后重购·客户端 = 拒绝叠加**(E99 拍)：输第 2 个码 → 弹「本设备已绑定其他授权码，请联系客服换绑」**+ 一行设备短码**(device_id 缩写，供用户报客服精确定位)；**绝不本地换绑**。
- ✅ **封停/删卡后重购·服务器 = `device_id` 内部主键**(E99 拍)：device_id 自动认「同一台手机」关联历史；用户对外**只报卡密/淘宝订单**(不用知道 device_id)；换机重装(device_id 变)退而用淘宝订单/旺旺ID 人工核。服务器后台 4 能力见 §7。
- ✅ **时间闸 = v1 只 T_soft 软引流**(E99 拍)：未授权走现有 `OFFLINE_FUNNEL` 软弹窗 + 临到期续费提醒；**登录砸门 T_login 降 v2**(无 Activity 锚点)。**首装 72h 内不撤 A2、超 72h 才撤**（见 §3 #1）；自然到期走 7 天、封停/删卡走 72h（D-021）。
- ✅ **散沙扩面 = 只杂项功能**(防撤回/定位/通知/未读)(E99 架构师拍死)：**密友隐藏四链(会话/朋友圈/通讯录/搜索)绝不进 RiskState 散沙**——它们 record-only 是故意(铁律29 + GUARD_GATE_TRUTH §4 防误伤正版)；篡改时密友隐藏的散沙靠 **registry 重签覆盖**，不靠 RiskState。
- ✅ **封停/删卡撤闸字段 = 信封 `rf`（wire 键·历史缩写，语义=封停/删卡）**(E99 批 · 块A L2 锁定)：**字段不用猜** —— 客户端 `AuthEnvelopeVerifier` **已在读** `rf`(JSON key `rf`，L2 实证)。契约 = 服务器照发 `rf=1` 即可（`rf` 仅作 wire/存储键保留；代码语义符号已改 `isCardRevoked` 系，D-020 §6）。
  - **信号链(块A 已落+自测 25/25)**：后台封停/删卡 → `cards.refunded_at`(服务器历史列名·wire 不动) → 心跳 → 信封签名 `rf=1` **+ 散沙(垃圾种子)** → 客户端读 `rf` → `markCardRevoked()` → **隐私 rf=1 立刻散 + A2 cardRevokedAt+72h 后撤(D-021)** → `K_CARD_REVOKED` 可信时间戳 latch(**可被有效授权恢复**·D-020)。**双保险**：客户端 latch + 服务器侧散沙(隐私也死)。
  - **客户端 ✅ 已落码(工作区·待验证)**：`markCardRevoked()` + `K_CARD_REVOKED` prefs + `isCardRevoked()` + `isAntiBanReady` 时间闸(封停 cardRevokedAt+72h) + 收 `rf=1` 隐私立刻撤 + latch `clearCardRevokedIfAuthorized` 可恢复。
  - ⚠️ **安全官复审 gate**：`rf` 进 Ed25519 签名覆盖(不可剥离) + 散沙复用 decoy = 唯一碰加密链的改动 → **部署前必过安全官复审**(块A 暂缓部署，复审随部署)。
- 🟡 **封停 72h 宽限后"悄悄失效"的渐进时长 = 默认复用现有离线渐进阶梯**(到期同款，不另造) —— 用户可调。
- ⚠️ **边缘(已知)**：license 已过期 + 封停/删卡 → `s=0` 客户端提前废包读不到 `rf`(概率低；块B `K_REFUNDED` latch 一次即永久缓解)。

## 7. 服务器后台 / 客服运维能力（块 A · 暂缓未建 · 本节为需求权威，建服务器照此做）

> 用户无服务器预算，块 A 暂缓；但需求在此**钉死**，将来建 `miyou-server` 照做。运维规则真源 = `guard-server_服务器运维` skill（该 skill 只放指针指向本节）。

| # | 能力 | 客服怎么用 | 客户端是否参与 |
|---|------|-----------|:---:|
| 1 | **DB 存** `device_id → [授权码历史 + 封停/删卡状态]` | 底座 | 否 |
| 2 | **激活判重**：第 2 个码激活 → 查同 device 已绑 → 返回「已绑定」 | 自动 | 是(收结论→拒绝叠加+显设备短码) |
| 3 | **查史**：按卡密/device_id 拉当前绑定 + 历史授权码 | 输卡密看「现在绑了啥」 | 否(客服后台) |
| 4 | **审计日志搜索**：每个激活/判重拒绝/封停/删卡事件落日志(卡密+device_id+时间+原因) → 客服输那个「提示重复」的卡密 → 搜到「为什么」(绑在哪台机/何时/封停删卡还是另一卡占了) | 输卡密查「为什么会这样」 | 否(客服后台) |

- 客户端**永远不碰**查史/审计接口(那是客服后台)；客户端只在激活时收 server 的「已绑定」结论 + 显示设备短码。
- device_id = **内部主键**(用户/客服都不直接念)；对外句柄 = 卡密 + 淘宝订单 + (冲突时)设备短码。
