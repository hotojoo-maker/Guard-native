## 2. 设计方案（在 `A2SignatureSpoof` 上扩，不另起炉灶）

### 2.1 新增 hook 面

- 现状：只 hook `ApplicationPackageManager.getPackageInfo(String,int)`。
- 新增：`ApplicationPackageManager.getApplicationInfo(String,int)`（`c$p.aa` / `normsg.u` 组走此读 `sourceDir`）。

### 2.2 包名轴（getPackageInfo afterHook 内增）

只在 `isDetectionCaller() && !self.equals(OFFICIAL_PKG)` 时：
- `pi.packageName → OFFICIAL_PKG`
- `pi.applicationInfo` → 走 §2.3 路径喂料

### 2.3 路径轴（`feedOfficialPaths`）

- `ai.packageName → OFFICIAL_PKG`
- 借同机真官方包 `com.tencent.mm` 的 `ApplicationInfo`：`sourceDir/publicSourceDir/dataDir/nativeLibraryDir` ← 官方真路径
- 官方包未装 → 字符串兜底 `self → OFFICIAL_PKG`
- `getOfficialAi` 一次性查 + 缓存 + 防重入（`inOfficialQuery`）

### 2.4 caller-selective（`isDetectionCaller`）

- 遍历 `Thread.currentThread().getStackTrace()`，命中 ANCHORS 才喂。
- ANCHORS（研究线基准）：`normsg.c$p` `c.p.aa` `WCProbe` `t8.c0` `platformtools.t8` `plugin.normsg` `bu5.a` `SayHi`。
- 目的：只喂检测/上报调用方；业务调用方（数据目录/provider/路径）原样返回，否则错值 → 崩。

### 2.5 只共存生效（天然开关）

- `self = BuildConfig.GUARD_WX_PKG`。官替 `self==com.tencent.mm`，包名/路径轴整段不装（喂官方=换官方，白费 + 多 hook 面）。
- 签名轴两版都装（两版都重签、签名都偏）；包名/路径轴只共存装。

### 9.2 网络安全官 → WARN（条件放行；R3/R4 = BLOCK 级前置）

> 2026-06-29 Vchat `guard_native-AJ30` 复评：未背书初稿，按 G6 读码（`A2SignatureSpoof.java` + 全仓 grep `getApplicationInfo` 零命中）后独立评。

**核实（读码）**：

- `getApplicationInfo` 全 Java grep 零命中 → 新增 hook 面属实。
- `A2SignatureSpoof.feedOfficial()` 只改 `signatures[]`+`signingInfo`、**直接改原 PackageInfo 未 clone**、有 `self` 守门 → §1 现状表属实。

**认可**：

- A2 料正确：喂包名/路径属保号轴，**不碰隐私 registry**（server-seed / fail-closed 不动，硬红线区分）。
- 不清数据(#5) · 不进已验证隐私 hook 回调体(#7，落点是 A2 安装器) · 纯 Java 不碰 native(铁律23)。
- 不误杀正版：官替 `self==官方包名`→整段不装（零影响）；共存正版喂官方=预期。

**⛔ R3 clone —— BLOCK 级（#9 命门），且比签名轴严格得多**：

- 根因：签名轴能直改原对象、未 clone 却过 L1，是因**业务方不读 `signatures`、只大血管读**，污染缓存无人被波及；但 `packageName/sourceDir/dataDir/nativeLibraryDir` **业务方高频读**（provider/资源/文件路径），直改污染 PM 缓存 → 业务方拿 `com.tencent.mm` → 找不到自身 `.mn` 数据目录 → 崩/数据错乱。
- 要求：必须 clone，且**深到 `applicationInfo`**（PackageInfo 浅拷贝不够，`applicationInfo` 是引用）。

**R3 clone 实现细节（落码照此）**：

- 拷贝方式优先 **Parcel 往返**（深拷贝彻底、不漏字段；`PackageInfo`/`ApplicationInfo` 均 `Parcelable`）：

```java
Parcel p = Parcel.obtain();
pi.writeToParcel(p, 0);
p.setDataPosition(0);
PackageInfo copy = PackageInfo.CREATOR.createFromParcel(p);
p.recycle();
// 只在 copy 上改：copy.packageName / copy.applicationInfo.sourceDir/...，再 param.setResult(copy)
```

- 开销控制：**仅在 `isDetectionCaller()==true` 时 clone**（大血管调用频率远低于全部 `getPackageInfo`，业务方走原路径零拷贝）。
- `applicationInfo` 判 null（部分 flag 下可能为 null）。
- **clone 失败 fail-open**：`Parcel` 异常 → `catch(Throwable)` → **不改 result、返回原对象**（宁露身份不崩业务；A2 闸本就 fail-open）。绝不允许「clone 失败仍改原对象」。

**⚠️ caller-selective × clone 双保险**：clone 防缓存污染（后续调用）；caller-selective（ANCHORS 命中大血管才喂）防当次误喂业务方。改后审必验 `isDetectionCaller` 漏判（露身份）+ 误判（崩业务方）两边界。

**⚠️ R4 兜底**：官方包未装时字符串兜底必须覆盖全 4 字段（`sourceDir/publicSourceDir/dataDir/nativeLibraryDir`），漏一个 = 身份不一致。

**真锁口径**：本设计不碰 `registry`/真锁（`recipeOk`/`getRecipe` 不受影响），不得当防破解进展。

**结论**：WARN·条件放行；**R3（clone 深到 `applicationInfo` + Parcel 方式 + 失败 fail-open）+ R4（兜底全字段）= 硬性 BLOCK 门槛**，不满足落码即 BLOCK。落码后必走改后审（R3 clone + caller 双边界）+ §7 五条 L1 + 出包前 `frida_stats`。
