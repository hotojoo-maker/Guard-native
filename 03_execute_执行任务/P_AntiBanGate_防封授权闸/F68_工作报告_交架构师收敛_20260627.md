## 二、关键发现（文档对齐重点）

### A. 密友散沙的「牙」= registry-cert crypto 绑定（最深 / 立刻 / NOP 不掉）【L2】

- `native_core/src/config_crypto.cpp::derive_registry_key()` 折入**运行时模块证书 SHA-256**（`g_binding`）；`ModuleMain` 读活 APK 证书 → `NativeBridge.setBindingMaterial(sha)`。
- 代码原注：「re-signed APK → wrong key → scatter; no binding → also wrong key (fail closed)」。
- 即：重签模块 → 证书变 → registry 钥匙错 → 解不开 → `recipeOk=false` → 密友隐藏 + 所有配方**立刻**散。
- **L1 现场佐证**（reboot 后日志）：`[native] certBind set sha256[0..3]=ca421ec3` → `[hb] registry after seed ... entries=5 ... recipeOk=true`。证书喂进 registry 解密，链路可见。
- **结论：不需要再加 Java `isActive` 散沙层（多余且更弱、可 NOP）。**

### B. 两条散沙线 · 时机不同（文档务必讲清，别再混）

| 线 | 触发 | 时机 | 管谁 | 强度 |
|---|---|---|---|---|
| crypto 证书绑定（registry key 折 cert） | 重签 | **立刻** | 密友隐藏（registry 全配方） | 强（NOP 不掉） |
| Java 绊线影子期（CompatProbe→markTampered） | 重签 / 改诱饵 | **7 天后** | 杂项（来电/通知/防撤回/伪装定位）+ 引流弹窗 | 可 NOP（故藏） |

- 密友走 crypto（密钥要么对要么错，无法「先正常 7 天再坏」，故立刻断）。
- 杂项 + 弹窗走 `CompatProbe.checkSignature/check` → `RiskState.markTampered` → 7 天影子期 → `TAMPER_FUNNEL` → `isTamperDegraded()` → 散沙 + `RiskPromptController` 引流。
- 两套配合，不矛盾。
