## 0. 一张总图（4 模块在真锁链里的位置）

```
卡密 → token(EnvelopeStore) → Ed25519 信封验签 + device 绑定(EnvelopeStore.getVerifiedCachedEnvelope)
          │                                         │
          │ server seed(k/n) ──→ NativeBridge.applyServerSeedAndReset ──→ SO decrypt_config
          │                                                                   │
   LeaseClock.trustedNow（防回拨授时）── 喂 → isLicenseExpired / 未来 isAntiBanReady          ↓
          │                                                          GuardRuntime.getRecipe（唯一配方出口，fail-closed）
   Bridge（lwxd/dvhsh/首装时间[新键]/名单/开关 持久化）                      │
                                                                     业务/防封 hook 按 recipe 命中 or 跳过
```

- **真锁牙**：`GuardRuntime.getRecipe` 出真 registry 的前提 = EnvelopeStore 验签过 + server seed 解开 SO。**没有合法 envelope → 必须散沙**（S3b 破防唯一判据）。
- **A2 同源横切**：EnvelopeStore L155 与 Bridge `dvhsh` 都吃 `AuthManager.computeDeviceHash`，A2 不修则两者一起塌（见各模块 §耦合）。

## 1. GuardRuntime（配方唯一出口 + 未来 `isAntiBanReady` 闸）

### 职责（L2，core/GuardRuntime.java）
- 加密 registry recipe 的**唯一出口**：`getRecipe(gateway,key)` / `isConfigReady` / `isSensitiveConfigReady` / `getRecipeOrFallback` / `getRecipeListOrFallback`。
- fail-closed：registry 不可用 → 返回 `""`（调用方跳过该 hook）。
- `isStrictRecipeMode()=!BuildConfig.DEBUG`：release 严格、不回退明文；debug 才给 fallback。
- 边界（注释自述）：config/key 层，**不读写 StateMachine / AuthManager / AUTH_***。
- **本轮要新增**：`isAntiBanReady()`（配方卡 §B；DESIGN §9）——**唯一 auth-aware 防封出口**。

### 落码前必须满足（go 条件）
1. `isAntiBanReady()` 时间线 **自算** `age = LeaseClock.trustedNow() - 首装时间`；**禁**复用 `LeaseClock.currentLevel()` 的 24/72/144h 离线阶梯（watch①，否则与隐私离线门连坐）。
2. `isAntiBanReady()` **吊** `EnvelopeStore.isAuthorizedNow()` + `LeaseClock`，**不是裸客户端布尔**（红线#1）。
3. 两闸独立：`isAntiBanReady`(A2) 与 `isConfigReady/isActive`(隐私) 各管各、互不散沙（DESIGN §1）。
4. A2 料走 `getRecipe` 同一出口、只进 `registry_pack`，**禁新增 a2_pack**（watch②）。
5. 必须是**真闸**：闸 false → A2 真的不装/卸，**不是 record-only**（对应「风险只记录未真降级」雷区）。

### 易错点 / 高危点
- 🔴 **TODO 未做（L2 注释实锤）**：`GuardRuntime` 顶部 `TODO Phase 1D-server: fold LeaseClock + RiskState into EncryptedConfigLoader so expired/tampered envelopes degrade to scatter` —— **现在过期/篡改信封还不会让 getRecipe 散沙**。落 `isAntiBanReady` 时若也只「记录不降级」=闸形同虚设。
- 🔴 release fail-closed：`getRecipeOrFallback` 在 strict 下 miss 返回 `""`，但**前提是调用方真的 skip**；A2 install 处必须 `if(getRecipe空) 不装`，不得自带 Java 明文 fallback（D5）。
- 🟡 `isAntiBanReady` 若读墙钟而非 `trustedNow` → 时钟回拨绕闸（红线#3）。

### 验收口径
- **L2**：jadx/源码核 `isAntiBanReady` 只调 `trustedNow`+`EnvelopeStore`，无 `System.currentTimeMillis` 直判、无新 pack、无明文 A2 料。
- **L1**：冷启 `adb logcat | findstr ANTIBAN-GATE` 见各分支（fresh/soft/login/kill）行为对；无合法 envelope 时 `getActiveRegistrySummary`=scatter、A2 不装。

### 与 A2 修复耦合
- 🟡 **时序**：A2 install 由 `isAntiBanReady` 门控，且**必须晚于** device 材料捕获 + 自读闸就绪（A2 方案 §1.3）；闸为 false 连 android_id afterHook 都不该装。

## 2. EnvelopeStore（信封/token 缓存 + `isAuthorizedNow` 真授权门）

### 职责（L2，net/EnvelopeStore.java）
- S2 信封/token 本地缓存（独立 SP `ncl_env`，不写 Bridge 保险区）。
- `isAuthorizedNow()` = `hasToken()` && 验签信封有效 && `!isLicenseExpired`。
- `getVerifiedCachedEnvelope()`（P0 硬化）：缓存仅对**同一 blob + 同一 deviceId**复用；任何手改 tk/bl/le → 重过 `AuthEnvelopeVerifier.verifyAndParse`（Ed25519 + device sanity）。
- `applyCachedEnvelopeSeed()` → `NativeBridge.applyServerSeedAndReset(k,n)`（喂 SO 种子）。
- `revokeKeepToken()`：撤本地授权但留 token（重连自愈）；`clear()` 不清密友名单（红线#5）。

### 落码前必须满足（go 条件）
1. **fail-closed 根锁**：无合法 envelope / 验签不过 / seed 解不开 → `isAuthorizedNow=false` 且 `applyCachedEnvelopeSeed=false` → 下游 getRecipe 散沙。**绝不**因「有 token」就放行。
2. P0 硬化不得削弱：缓存复用键必须仍含 **blob + deviceId** 双绑定；deviceId 必须是**真值**（见 §耦合）。
3. `isLicenseExpired` 继续走 `LeaseClock.trustedNow`（不信墙钟，红线#3）。
4. 撤授权 / 解绑只清信封元数据与（如需）token，**不清用户密友/密群/密码**（红线#5/#6）。

### 易错点 / 高危点
- 🔴 **A2 同源直接受害点（L2 实锤，L155）**：`getVerifiedCachedEnvelope` 调 `AuthManager.computeDeviceHash(sAppCtx)`，A2 不修则 deviceId 被灌成官方 SSAID →（a）`verifyAndParse` 用错 deviceId → 信封 device 绑定校验失败 → 返回 null → `isAuthorizedNow=false` → **误杀正版**；或（b）全机 deviceId 收敛同值 → **跨机信封重放**风险。
- 🟡 缓存 blob 内含短命 key 材料 k（离线宽限必要代价）；威胁模型靠「短命+设备绑定+服务端轮换」，**不得**因此把租约判松。
- 🟡 `sAppCtx==null` 早期调用返回 null（安全降级）——确认 A2/闸不会在 init 前误判「未授权→解体」。

### 验收口径
- **L2**：源码核 `isAuthorizedNow` 三段（token+验签+未过期）齐全；`getVerifiedCachedEnvelope` 仍 blob+deviceId 双绑定。
- **L1**：① 改 1 字节 blob → 验签失败、`isAuthorizedNow=false`；② 无 envelope → `recipeOk=false`/scatter；③ 装 A2 后 `isAuthorizedNow` 不被同源误杀（正版仍 true）——**与 A2 D1 同批装机**。

### 与 A2 修复耦合（🔴 直接，最紧）
- `computeDeviceHash` 必须经 A2 自读闸透传真值；**A2 不修 = EnvelopeStore 必坏**。本模块共审与 A2 修复**强制同批**，不得分开放行。

## 3. LeaseClock（防回拨授时 + 离线风险等级）

### 职责（L2，core/LeaseClock.java）
- `trustedNow()` = `last_server_now + Δelapsed`，回拨/重启回绕时退回 `max_trusted_now` 历史水位；从未心跳 → `max(墙钟, 水位)`。
- `currentLevel()` 输出时间/断网风险等级；阶梯 WARN 24h / DEGRADE 72h / FUNNEL 144h（常量，对齐 `NativeBridge.GRACE_*`）。
- `onServerHeartbeat` 写 `last_server_now` + 抬水位；`isLeaseExpired`/`offlineMillis`/`isClockSuspicious`。

### 落码前必须满足（go 条件）
1. `isAntiBanReady` **只借** `trustedNow()` 自算 age，**不借** `currentLevel()`/`GRACE_*` 阶梯（watch①，两闸不连坐）。
2. 从未心跳分支保持 **CLEAN 不凭空降级**（红线#4 不误杀真用户）；防封解体靠 isAntiBanReady 自算 age，不靠 LeaseClock 降级。
3. 防回拨水位 `max_trusted_now` 逻辑不得被改弱（回拨不能续命）。

### 易错点 / 高危点
- 🟡 **时钟回拨接受 = 已知 trade-off（决策13）**：从未心跳时 `trustedNow=max(墙钟,水位)` → **首装 1h/2h（软引流/登录砸门 UI）判定在「首刻、未联网」时锚在墙钟（解体已改影子期+不续命，A51）** → 改机器时间可绕首装计时（LeaseClock 防回拨只在曾联网后生效）。属固有缺口，需 S9 服务器时间尽早收紧（L3）。
- 🟡 **代码 vs 文档口径出入（标 ❓）**：类注释写「服务器心跳端点未接」，worklog 写「LeaseClock 已接信封授时」——`onServerHeartbeat` 实际由谁驱动、首装机是否真有服务器基准，**需 L1 确认**（影响首装解体判定可信度）。
- 🟡 阶梯是明文常量（轻迷彩），后续应随 `risk_pack` 服务端下发（周期外置）。

### 验收口径
- **L2**：源码核 `isAntiBanReady` 不引用 `currentLevel/GRACE_*`；水位防回拨分支在。
- **L1**：① 改机器时间回拨 → `trustedNow` 不倒退、租约不续命；② 首装无网 → isAntiBanReady 按 age 走、不被 LeaseClock 离线阶梯连坐；③（接服务器后）回拨被服务器时间纠正。

### 与 A2 修复耦合
- ⚪ 间接：LeaseClock 不读 android_id；经 envelope→租约 间接依赖 device 绑定。共审只需确认「device 变动不会经 LeaseClock 误判租约」，预期 not-affected。

## 4. Bridge（持久化薄层 + device 绑定存储 + 首装时间新键）

### 职责（L2，core/Bridge.java）
- SharedPreferences 薄封装（namespace `g_a7f2`，短哈希键）；存密友/密群名单、各功能开关、授权绑定（`lwxd`=licensedWxid / `dvhsh`=deviceHash）、myWxid 等。
- `setDeviceHash/getDeviceHash`（`dvhsh`）：授权绑定阶段存 `computeDeviceHash` 结果。
- 状态机键 `smst` 走 `commit` 强同步；其余 `apply`。

### 落码前必须满足（go 条件）
1. **新增「首装时间」键**：用 **4 字符短哈希**键名（watch / §6.7），**不出现** `install_time` 等明牌词；写入时机 = 首次冷启动一次、之后只读不被重置。
2. `dvhsh` 存进去的必须是**真 device hash**（A2 自读闸保证）——绑定阶段一旦存错=永久绑错。
3. 不在 Bridge 落 `grace_until`/`isVip`/`risk_level` 等明牌状态键（黑盒化 DESIGN §5.3；value 可加密、key 短哈希）。

### 易错点 / 高危点
- 🔴 **绑定期污染 = 永久错**（L2/A2 耦合）：`bindAccount`→`setDeviceHash(computeDeviceHash)`；若 A2 在绑定前已灌官方值 → `dvhsh` 永久存官方值 → 与 EnvelopeStore device 校验长期错位。
- 🟡 **namespace 现硬编码 `g_a7f2`**（L2）：注释称 seed-based，但实为单值；多客户 seed 化（§6.7）未落，属混淆面缺口（非本闸阻塞项，登记）。
- 🟡 首装时间若用墙钟写入 → 与时钟回拨 trade-off 叠加；建议写入时同记一份 `trustedNow` 基准（设计待定 ❓）。

### 验收口径
- **L2**：jadx 搜不到 `install`/`grace`/`isVip` 明文键；首装时间键为 4 字符短哈希。
- **L1**：① 首次冷启动写一次首装时间、二次冷启不变；② 装 A2 后 `getDeviceHash` 仍真值（与 EnvelopeStore 一致）。

### 与 A2 修复耦合（🟡 直接：存值）
- `dvhsh` 写入依赖 `computeDeviceHash` 真值 → A2 自读闸必须覆盖 `bindAccount` 路径；与 A2 修复同批审。
