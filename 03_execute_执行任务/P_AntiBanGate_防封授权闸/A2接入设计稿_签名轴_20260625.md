## 0. 一句话

把研究线已 L1 证明的「骑 `getPackageInfo` 咽喉、灌官方签名」从 frida 实验**接进产品模块**：afterHook 自身包签名读取，喂官方 DER；料锁进加密 registry（盗版解不出 → A2 散沙）；只受防封闸 `isAntiBanReady()` 门控，不连坐隐私 `isActive()`。

## 1. 范围（本期只做签名轴；其余留位、分期）

| 轴 | 本期 | 说明 |
|---|---|---|
| **签名轴（signatures[] + signingInfo）** | ✅ **做** | 非 root 可行、已 L1 全料证（见 §2）；本稿主体 |
| android_id（官方 SSAID） | ⬜ 留位（A2-3） | 喂点已 L1 跑通；算法同构但 `user_key` 每机不同且 root-only，非 root 精确值源单独算账（见 `DESIGN §4.1`） |

## 2. 证据基线（L1，本期设计的事实依据）

- **能抓**（官方包 8.0.71 冷启）：签名所有 Java 读取者（`c$p.aa/ad/af` + `t8.c0` + `bu5.a`）**全经 `getPackageInfo`/`Signature.toByteArray`**，咽喉是共同上游 → `recon/A2_RIDE_TEST_20260625.md`。
- **能骑 + 全料**（mn complete 日志）：喂 `signatures[]`（c$p.ad 读 `18c867f0`）+ **`signingInfo`（bu5.a.a 读 `18c867f0`）** → **NON-OFFICIAL 残留 = 0**。
- **硬要求**：签名轴**必须同时喂两条**——`signatures[]`（`GET_SIGNATURES` 路径）**和** `signingInfo`（`GET_SIGNING_CERTIFICATES` 路径，Flutter `bu5.a.a` 专走它）。只喂前者会漏 bu5（实验首轮已踩，见 complete 前一版）。
- **判定（2026-06-26 · L1 · 底座 8.0.71）**：**「咽喉能骑 + 能喂官方值」成立**。能喂 = `getPackageInfo` afterHook 灌官方 DER；能骑 = 灌后 `c$p.ad` 实读官方 `18c867f0`（喂前 `e89b158e`）、未绕过。证据 = 防封官 skill 实测手法库 #9（dimmod_v2 SPOOF）+ `recon/A2_RIDE_TEST_20260625.md` + `recon/a2feed_dimcollect_mn_complete_20260625.log`。⚠️ 此判定锁**能力**；服务器是否据签名判罚仍 **L4**（防封官红线 #1/#9：无服务器石锤不写必封 / 必安全）。

## 3. 挂点（代码 AI 照此实现）

**新增类** `core/A2SignatureSpoof.java`（产品里现无任何 A2 代码，全新）：

- **Hook 1**：`PackageManager.getPackageInfo(String pkg, int flags)` afterHook
  - 仅当 `pkg == 自身包名`（`BuildConfig.GUARD_WX_PKG`）才动；他包**原样返回**。
  - `flags & GET_SIGNATURES` → 把 `result.signatures[]` 替换为官方 DER 构造的 `Signature[]`。
  - `flags & GET_SIGNING_CERTIFICATES` → 把 `result.signingInfo` 替换为官方 DER 的 `SigningInfo`（覆盖 `getApkContentsSigners()`/`getSigningCertificateHistory()` 返回官方）。⚠️ 这条是 bu5.a.a 闭环的关键，**不可省**。
- **Hook 2**（同类，签名读取另一路径，冗余兜底）：若 `Signature.toByteArray` 被某 caller 直接调用且无法只经 getPackageInfo 覆盖到——**先不全局 hook**（红线），靠 getPackageInfo afterHook 覆盖；L1 发现遗漏 caller 再按 caller-scope 补。
- **安装位置**：`ModuleMain` 内，**紧接 `bindSigningCert(app)` 之后**（L151 区域）；A2 安装前必须满足 §5 门控 + §6 设备材料预热。
- **复用研究实证**：实现细节对齐 mn complete 日志里已验的 spoof 方式（dimcollect SPOOF 路径），不要另发明。

## 4. 料（官方 DER，锁进加密链）

- 料 = 官方签名 DER（`md5=18c867f0717aa67b2ab7347505ba07ed`，len=751）。
- **进 `registry_pack`（加密）**，不明文写死：只有**服务器种子 + 验签信封 + SO `decrypt_config()` 成功**才解得出（`DESIGN §5.1`）。
- 取件口：走 `GuardRuntime.getRecipe(...)` / `nativeGetRecipe`（与现有 registry 同一出口），新增一个 gateway key（如 `a2.sig.official_der`）。
- **fail-closed**：解不出 → 返回空 → A2 **不安装 hook**（散沙），**release 禁明文 fallback**（DEV/DEBUG 可留 fallback 方便开发，`BuildConfig.DEBUG` 门控）。
- gen 脚本：官方 DER 进 `native_core/registry_8071.json` → `gen_registry_cipher.py` 重生成 `.inc`（与现有 registry 同源同流程；改 KDF/料须三端测试向量对账，见安全官 skill）。

## 5. 门控（A2 独立闸，不连坐隐私）

- **新增** `GuardRuntime.isAntiBanReady()`（产品现无此函数）。
- **本期最小真闸**（不是裸客户端布尔，红线#1）：`isAntiBanReady() = EnvelopeStore.isAuthorizedNow() && GuardRuntime.isConfigReady() && a2 料 recipeOk`。
  - 即：有有效授权信封 + registry 解开 + 官方 DER 料解得出，才装 A2。
  - 盗版无种子 → 料解不出 → `isAntiBanReady=false` → A2 散沙（不再加工喂官方 → 咽喉只剩生料 → 不再保号；官方怎么判我方读不到、不预测）。这是反白嫖闭环（`DESIGN §0` 闸 B）。
- **不连坐**：A2 只看 `isAntiBanReady()`；隐私功能仍走 `isActive()`。两闸独立（红线）。
- **完整时间闸（T_soft/T_login/T_kill/影子期）= A2-4 后补**；本期到期宽限沿用授权链，不在本稿展开。
- **✅ 找授时点（2026-06-26 已定 · 两源喂同一地板）**：授时点 = `LeaseClock.trustedNow()`（**不信墙钟**，红线 #3；A2 时间线 = `trustedNow − 首装时间`，不复用 `currentLevel()` 的 24/72/144h 阶梯防连坐）。`trustedNow` 吃**两个独立服务器时间源**喂的 `max_trusted` 地板：
  - **① 我方服务器** `sn`（Ed25519 信封 → `GuardHeartbeat:120 onServerHeartbeat`，已有）。
  - **② 官方授时（改表杀不掉）** = `jy0.hd.b()`（微信 `MicroMsg.TimeHelper` 地板值；L1 实证回拨墙钟 2 天纹丝不动、按真实秒走。`hd.c()` 跟墙钟、改表能拨 → **禁用**）。接法：新增 `LeaseClock.noteOfficialTime(ms)`，**只抬 `max_trusted`、绝不降** + 未来时间上限兜底；纯读、零新增检测面（守铁律5/KPI）、过授权检查官。
  - ⚠️ **`field_conversationTime` 作废，以 `DESIGN.md §6` 为准**：旧「`ConvFilter.extractConvTime` → `field_conversationTime`（L1 2026-05-29）」口径已弃——要登录 + 有会话才有值、空闲偏旧；`jy0.hd.b()` 不依赖会话、改表杀不掉，取代之。
  - **为什么要 ②**：补「时间冻结」洞——单靠 ① 时，盗版**屏蔽我方服务器 + 反复重启**（`elapsedRealtime` 归零）可把 `trustedNow` 冻住 → 影子期永不到期 → 白嫖不死；② 独立于我方服务器、改表杀不掉。两源喂同一地板，停表需同时干掉两个。
  - **登录依赖（边界）**：登录前微信不主动对时，全新装 / 从没登录过 → `hd.b()` 无值 → 这类无微信号 fail-open 装（不误杀）；有值后只偏保守、不误杀。

## 6. 设备材料顺序（E9×A2 同源必修，防全机塌）

- A2 喂 android_id 是 A2-3 的事；**但本期仍须守顺序**，因 A2 install 早于很多链：
  - `AuthManager.rawAndroidId(ctx)` **先 memoize 真值** → `setDeviceMaterial` → **再** install A2。
  - 未缓存真设备材料则**不装 A2**（`DESIGN §四` device×A2 同源）。
- 本期不碰 `Settings.Secure.getString`（那是 A2-3）；但实现 A2SignatureSpoof 时**不得**顺手读/污染设备材料读点。

## 7. 红线（违任一即停，BLOCK）

1. **只动自身包** `getPackageInfo(self)`；他包（`bin.mt.plus`/`com.topjohnwu.magisk` 等）**原样返回**。
2. **禁全局 hook** `Signature.toByteArray()` / `getPackageName()`（误伤 + 363 处崩）。
3. **零环境读取**：A2 不读 `ro.boot.*`、不枚举包、不跑 logcat（守铁律5 / 防封 KPI）。
4. **fail-closed**：料解不出 = 不装 hook（散沙），release 无明文 DER fallback。
5. **不进已验证 hook 回调体**；A2 是独立新类，不动隐私 Filter。
6. **不破坏原版**：afterHook 仅改自身包返回值，不动微信本体流程。
7. secret / 官方 DER 原文不进 git/log 明文（registry 加密；日志只打 `md5[:8]`）。

## 9. 验收 DoD（装机 L1，缺一不可）

- **能抓能骑**：冷启 logcat 见 A2SignatureSpoof 装载；`c$p.ad`/`bu5.a.a` 读到官方 `18c867f0`；**NON-OFFICIAL 残留 = 0**（对齐 complete 日志口径）。
- **fail-closed**：无 server seed → 官方 DER 料散沙 → A2 不装（`isAntiBanReady=false`）；有 seed → 装。
- **不误伤隐私**：`recipeOk=true`、密友隐藏照常（A2 是加法，不动 `isActive()`/Filter）。
- **KPI 不变**：喂料前后 `frida_stats`（verifiedbootstate/normsg/PROP/CONN）**变化量≈0**（A2 只改返回值、无新增环境读取；并行实验给数）。
- **release 无明文**：`strings`/jadx 搜不到官方 DER 明文（在加密 registry）。
- 日志原文落 `recon/` / 当期 worklog（L1）。
