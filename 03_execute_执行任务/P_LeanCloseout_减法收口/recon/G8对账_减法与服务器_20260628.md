## B. 服务器侧 — dm 回填率（Batch3 解冻前置）

**问题**：按设备 wrap S_rel 覆盖率（dm 回填率）到没到 90%？→ **没到，~25%。**

证据链：

1. **门槛定义**：`REVIEW_2026-06-27.md §B-1` —「活跃设备 dm 回填率 **≥ 90%**……**当前 ~25%**」（L2，文档实证）。
2. **指标算法**（`db.py:1588-1590`，L2）：`dm_backfill_rate = round(100 * dm_devices / total_devices)`，`dm_devices = COUNT(DISTINCT CASE WHEN dm<>'' THEN device_id)`（:1563），按 `release_id` 分组。即「已回填 dm 设备 / 该线已知设备」。
3. **dm 写入门**（`db.py:_store_device_dm` :530-536，L2）：客户端上报 dm 先过 `dm_self_check(dm,did)`（`dm[:16]==device_id`）才落库 → 回填依赖客户端 Batch1 已发版 + 设备活跃心跳，故爬升慢。
4. **实时值未取（L4 边界）**：权威实时数在 prod `zxmqq.shop` 的 `auth.db`，需 SSH 核 `length(dm)>0` 占比或读 `/admin/api` 的 `dm_backfill_rate`；本地 `I:\miyou-server` 无 `auth.db`（只源码），**只读红线下未 SSH**。故采信文档 L2 值 ~25%。
