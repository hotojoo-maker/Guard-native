# 用户使用指南 — 给不懂编程的人用 AI 管项目

> 这份文档是给用户看的。  
> 你不需要懂代码，只要按这里复制提示词、检查清单、要求 AI 汇报即可。  
> AI 每次接手本项目时，也必须阅读并遵守本文件。

---

## 1. 你每次开新聊天时，先复制这段给 AI

```text
你现在接手 guard_native 项目。

我不懂编程，所以你必须按中文清单一步一步做，不要埋头苦干。

开工前必须先读：
1. CLAUDE.md
2. docs/AI_WORKFLOW_CHECKLIST.md
3. docs/USER_AI_USAGE_GUIDE.md
4. 当前阶段相关的 docs/README.md + docs/HOOK_MAP_8071_AUTHORITATIVE.md
5. 如果要尝试方案，先查 refs/FAILURE_LOG.md

要求：
- 只做当前阶段，不要跨阶段乱做。
- 不确定就先问我，不要自己猜。
- 任何结论都要说清楚依据来自哪个文档、哪个函数、哪个测试现象。
- 需要我操作手机时，必须一步一步告诉我，每一步等我确认后再继续。
- 不允许让我联网测试，不允许加入联网、授权、反调试。
- 崩溃次数多有风险，所以真机测试前必须先说明测试步骤、预期现象、失败后如何停止。
- 每完成一个阶段，必须更新 docs/AI_WORKFLOW_CHECKLIST.md，在里面打钩并写实际结果。
- 遇到坑、失败、崩溃、走不通，必须主动提醒我总结到 refs/FAILURE_LOG.md 或 docs/AI_WORKFLOW_CHECKLIST.md。

现在请先告诉我：当前应该做哪个阶段、你准备改哪些文件、我需要配合做什么。不要先写代码。
```

## 5. 如果发生崩溃，复制这段

```text
微信发生崩溃，请先停止继续尝试。

请你先做三件事：
1. 总结最近改了哪些文件和函数
2. 判断最可能导致崩溃的点
3. 告诉我需要收集什么信息，比如 logcat 关键字、复现步骤、崩溃发生时我点了什么

在没有明确原因前，不要继续让我反复打开微信测试。
崩溃次数多有封号或风控风险，所以必须先降低测试频率。
```

```text
确认方式：我回复你什么

每次只给我一步，不要一次给很多步。
```

## 7. 手机测试的安全规则

### 必须遵守

- 测试本地功能，不要让手机联网测试。
- 不要登录新号反复测试。
- 不要短时间反复让微信崩溃。
- 不要连续重启微信很多次。
- 不要测试没说明清楚的 APK。
- 不要让 AI 同时改很多功能后再让你测试。

### 推荐做法

- 每次只测一个功能。
- 每次测试前让 AI 说清楚“预期现象”。
- 出现一次崩溃，先停下来总结。
- 出现两次相同崩溃，不要继续点，先查原因。
- 出现三次以上崩溃，必须回退或禁用新改动。

### AI 必须提前说明

每次让你测试前，AI 必须告诉你：

| 项目 | 必须说清楚 |
|------|------------|
| 测什么 | 比如“会话隐藏” |
| 怎么测 | 你要点哪里 |
| 预期结果 | 正常应该看到什么 |
| 异常结果 | 什么情况算失败 |
| 停止条件 | 什么时候不要继续测 |
| 是否联网 | 必须默认不联网 |

## 8. 踩坑需要写吗？

需要写，而且很重要。

本项目最怕 AI 忘记以前失败过的方案，然后重复尝试，导致原地转圈甚至崩溃。

### 哪些东西必须记录

| 情况 | 写到哪里 |
|------|----------|
| 某个方案试了会崩溃 | `refs/FAILURE_LOG.md` |
| 某个 hook 点确认有效 | `docs/README.md + docs/HOOK_MAP_8071_AUTHORITATIVE.md` |
| 某个阶段完成或失败 | `docs/AI_WORKFLOW_CHECKLIST.md` |
| 某个功能状态变化 | `refs/FEATURE_MATRIX.md` |
| 手机测试步骤和结果 | `docs/AI_WORKFLOW_CHECKLIST.md` 的实际结果 |

### 失败记录要写什么

失败记录不要只写“失败了”，要写清楚：

```text
日期：
阶段：
尝试方案：
改了哪个函数：
复现步骤：
实际现象：
崩溃/错误信息：
判断原因：
以后禁止什么：
```

## 9. 工具使用规则

### AI 可以做

- 读取项目文档。
- 修改项目文件。
- 编译 APK。
- 查看本地构建错误。
- 写总结文档。
- 根据你提供的现象分析问题。

### AI 不应该擅自做

- 不应该让手机联网测试。
- 不应该加入任何联网逻辑。
- 不应该加入授权、激活码、服务器验证。
- 不应该加入反调试。
- 不应该在你没确认时大改很多文件。
- 不应该让你连续崩溃测试。
- 不应该跳过文档直接写代码。

### 需要先问你的情况

AI 遇到下面情况必须先问你：

- 要安装 APK 到手机。
- 要你重启微信。
- 要你打开 LSPosed。
- 要你清数据、卸载、重装。
- 要你联网。
- 要测试可能导致微信崩溃的功能。
- 要改动当前阶段以外的功能。
- 文档之间有冲突。
- 结论没有足够依据。

## 10. 你怎么看 AI 有没有乱来

如果 AI 做得对，它会经常说：

- “我现在只做阶段 1。”
- “这次会改这几个文件。”
- “这个 hook 点依据是 `docs/README.md + docs/HOOK_MAP_8071_AUTHORITATIVE.md`。”
- “这个方案不能用，因为 `refs/FAILURE_LOG.md` 记录过会崩溃。”
- “需要你操作手机，我一步一步说。”
- “这一步完成后我会更新清单。”

如果 AI 这样做，你要小心：

- 一上来就写代码，不说明阶段。
- 让你直接装 APK，但不说测试风险。
- 一次让你做很多手机操作。
- 崩溃后还让你继续反复打开微信。
- 说“应该可以”，但不给依据。
- 想提前做 Pine、SO、授权、联网。
- 不更新 `docs/AI_WORKFLOW_CHECKLIST.md`。

## 12. 当前项目建议你怎么推进

现在不要急着做朋友圈、通讯录、Pine、SO。

推荐顺序：

```text
1. 阶段 1：最小工程骨架
2. 阶段 2：F04 会话隐藏最小验证
3. 阶段 3：F04 稳定补强
4. 阶段 4：隐藏名单配置
5. 阶段 5：F05 朋友圈隐藏
6. 阶段 6：F07 通讯录隐藏
7. 阶段 7：性能优化
```

每次只做一步。  
做完一步，打钩，写结果，再做下一步。

你只要记住这句话：

```text
AI 不确定就问我；需要我动手机就一步一步；出问题就先总结；完成一步就打钩。
```
