## ① 大白话

- **出货形态 = LSPatch 打包型 APK**：把模块（含 `libguardcore.so`）用 LSPatch **重新打包进**原版/克隆微信 APK，装的是新微信。LSPosed 独立模块 = 开发/smoke 历史形态，非出货默认。
- **两条独立发行线**，互不覆盖：
  - **官替版**：宿主包名 `com.tencent.mm`，装前需卸官方，体验最接近原版。
  - **共存版**：宿主包名 `com.tencent.mn`（首发已定死），与官方包并存。
- **一个发行包 = 一个 release_id = 一份 registry_cipher = 服务器一条 release_line + 一份 s_rel**。
- **v2「一套配方」（D-026，2026-06-30）**：官替 + 共存**共用同一把 release 签名**（`e3e13a49`）+ **同一份** `registry_cipher.inc`；区分只靠**包名 + release_id**。

## ④ 发版 5 步流水线（详见 RELEASE_RULES「s_rel 轮换 + 双版本 LSPatch 发版工作流」）

- **A 换 s_rel（可选）**：改 `release/secrets/<id>.json` 的 `s_rel_b64`（新 32B，`wrap_key` 不动）→ `python tools/gen_registry_cipher.py --recipe …` 重生成 `native_core/src/registry_cipher.inc`；两边 `sha256(s_rel)[:8]` 对齐。
- **B 出包（发版候选强制 Release 变体）**：`./gradlew :assembleOfficialRelease` / `:assembleCoexistRelease`，自动跑泄漏硬闸。Debug 变体只作模块更新/公告/C2-smoke，cert mismatch 注定 scatter，**不出货**。
- **C LSPatch 重打包**：**步骤 0** 先把克隆/非 `e3e13a49` 宿主用 `apksigner sign --ks guard-native-official-release.jks` 真重签为 `e3e13a49`；再 `java -jar 02_tools_工具/lspatch.jar <重签宿主> -m <flavor 模块APK> -l 2 -k signing/guard-native-official-release.jks … guardofficial … -o 02_tools_工具/lspatch_out -f`。一键：`tools\lspatch_pack.ps1 -Flavor <official|coexist> -BuildType release -Clean -Build`（commit `2cd643c`）。
- **D 服务器同步（交服务器运维）**：`I:\miyou-server\config.py` 的 `GUARD_REL_KEYS[<id>].srel` 换同一新 s_rel + `release_lines` 登记；统一入口 `python deploy.py`（默认只主节点、`--all` 才带备节点=备机未购勿加；旧 `deploy_release_health.py` 已弃）；`config.py` 不在 `standard`/`code` 集，用 `p1c` preset 单独推（核基线+备份+重启）。
- **E 装机 L1**：冷启 `available=true`/`role=1 MAIN`/`BATCH1_VERIFY PASS`/`certBind=e3e13a49`；心跳后 `recipeOk=true`（entries=5）、`PHASE1A PASS`（prod_server_lock 下 `PHASE1B~1E` 未拿 server seed 前 FAIL 属预期，非阻塞）。日志落盘才算发布候选。

## ⑤ 签名 / 证书真相（易翻车，出货前必核）

- 发版签名：`signing/guard-native-official-release.jks`（alias `guardofficial`，密码在 `signing/keystore.properties`，gitignore）；官替 + 共存**同一把 → cert `e3e13a49`**（v2 D-026）。

- **cert binding 真相（F-43 / D-030 · L1 实证）**：LSPatch `-l 2` sigbypass 运行时返回的是**宿主原始签名**，不是 LSPatch `-k`。所以克隆宿主（原始 `a40da80a`）/ 官方原版（`0fe4ff85`）**必须先 apksigner 重签 `e3e13a49`** 再 LSPatch，否则装机 `[native] certBind` ≠ EXPECTED → A2 不装 + registry scatter。
- `apksigner verify --print-certs` **只看文件级**，不证明运行时绑定 → **必须 logcat 实证** `certBind set … =e3e13a49`。
- registry_cipher 绑 `e3e13a49`、**两线共用一份**（per-flavor `registry_cipher_coexist.inc` 已退役）。
