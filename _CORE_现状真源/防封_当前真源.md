## ① 大白话

- 防封不是"造检测"，是**中间程序骑在官方查身份的咽喉上**（`getPackageInfo` → native `c$p`），**灌官方值让我方数据读出来像「官方、正常」**（签名 / android_id / 包名），尽量不被判异常。
- **只做一件事 = 让数据正常**（尽力、**非保证**）。官方最终怎么判、加密直发它服务器，**我方读不到、不预测、不保证保号**。
- **顺手借官方的眼睛**读输入变没变（签名被换 / 包被改）= 抓改包破解 → 散沙 / 影子期。
- **零环境读取**：`ro.boot.*` 官方自己读，我方零读（守 KPI；第三方读 verifiedbootstate 自伤）。root 不硬查、付费即正版。

## ② A2 三轴（官替 vs 共存 · 用户 2026-07-01 核对 · 真源 SSOT §1.1）

| 轴 | 官替版 | 共存版 | 为什么 |
|---|:--:|:--:|---|
| **签名** | 要喂 | 要喂 | 两形态都重签、签名偏离官方 DER（硬轴，L1 已证）|
| **android_id / SSAID** | 要喂 | 要喂 | SSAID 跟签名 key 派生、重签后偏；喂**本机**「官方 DER 对应 SSAID」（算法同构但**每机不同**、非全球一个 hex）|
| **包名 / 路径** | 通常不需要 | **要喂** | 官替已占官方包名 `com.tencent.mm`；共存 `com.tencent.mn` 不同，需在检测 caller（`normsg`/`bu5`/`c$p`）处**选择性**灌官方包名，禁全局改 `getPackageName` |

- 一句话：**官替 = 签名 + android_id；共存 = 再加包名。**
- **共存包名铁律**：禁止把代码里 `.mm` 粗暴全替 `.mn`——运行 / 作用域 / 数据目录 / native 期望包名用**真实共存包名**；只在**官方检测咽喉**灌官方包名 / 路径 / DER。签名要同时覆盖 `signatures[]` + `signingInfo` 两条读取路径，只改一条会漏。
