## ① 大白话

- **核心检测轴 = 是否官方（签名 / 身份）**。这才是官方真正区分的硬轴。**root / 解锁本身正常、非封因**（L1：开发机 root 一月零封、官方包读 unlocked 不 kill）。
- **核心打法 = 中间程序「掐官方检测的咽喉、骑它脖子上」**：不自己造检测（造 = 新增检测面 = 自找风险），只卡在官方身份检查的唯一咽喉 `getPackageInfo` → native `c$p`。
  - **一灌（让数据正常）**：来查身份的，灌**官方值**（签名 / android_id / 包名 → 官方）→ 我方数据读出来尽量像官方正常输入 → **尽量**不被判异常（尽力、非保证、官方怎么判我方读不到、不预测）。
  - **一读（抓改包）**：顺手借官方这只眼读输入 —— 签名被换 / 包被改 → 散沙 / 影子期，让破解者白忙。
- **env 零读取**：`ro.boot.*` 始终官方自己读，我方零读取（守 KPI：第三方读 `verifiedbootstate` +1 自伤）。
- **诚实边界**：咽喉只读得到官方查的**输入**（签名 / 包名，走 Java 抓得到）；官方最终判分加密直发其服务器、我方读不到。「让数据正常」= 尽力**非保证**；不写「保证保号 / 防住封」。

## ② A2 三轴（官替 vs 共存 · 你要的口径）

| 轴 | 官替 `com.tencent.mm` | 共存 `com.tencent.mn` | 说明 |
|---|:---:|:---:|---|
| **签名轴** | 要喂 | 要喂 | 两形态都重新打包/重签，签名都偏离官方 DER；**签名是已证硬轴**。喂官方 DER `18c867f0`，须同时覆盖 `signatures[]` + `signingInfo` 两条读取路径。 |
| **android_id / SSAID 轴** | 要喂 | 要喂 | SSAID 跟签名 key 派生，重签后偏。喂**本机**「官方 DER 对应 SSAID」（算法 HMAC-SHA256 同构、但 `user_key` 每机随机 → 输出每机不同，非全球共用一个 hex）。 |
| **包名 / 路径轴** | 通常不需要 | **要喂** | 官替已占官方包名；共存包名不同，需**仅在检测 caller 下**选择性灌官方包名/路径，**禁止全局改 `getPackageName`**。 |

> 一句话：**签名 + android_id 两形态都要照顾；包名/路径主要是共存的额外轴。**
> **共存包名铁律**：禁止把代码 `.mm` 粗暴全替 `.mn`。运行/作用域/数据目录/native 期望包名用**真实共存包名**；喂官方检测咽喉的身份输入用**官方包名/路径/DER**。

## ⑥ 反检测铁律（收口在防封官 · 详 CLAUDE §三）

- 禁读 `ro.boot.*`（Matrix 反向 hook 监控）。
- 守 LSPosed 进程白名单：只 `com.tencent.mm` 主进程 + `:push`（仅 badge/unread 最小拦截）；永久禁 `:sandboxed_process`/`:isolated_*`/`:appbrand*`。
- 禁 `getRunningAppProcesses`（沙箱进程无权限 FATAL）。
- 不引入底层注入三件套（Pine/bypassmm/shadowhook）；不注入微信 JNI 链（F-23）。

## ⑦ 已证 vs 待办 / 矛盾（诚实）

- **L1 已证**：签名轴经 `getPackageInfo`(Java) 读、A2 喂官方 DER 后 `c$p.ad` 读到官方 `md5=18c867f0 len=751`（2026-06-19 SPOOF 复验）→ A2 充分覆盖 c$p 签名读取。
- **🟡 待 L1 装机**：A2 时间闸 / 官方对时第二源 / latch 可恢复均已落码（L2），无装机日志不得称 L1（SSOT §3.2/§8）。
- **残留非签名面（签名喂官方不治）**：`c$p.aa` 仍枚举 `magisk`/`gsf`/`gms`/`vending`（环境/root 软信号）；共存 `com.tencent.mn` 包名本身仍是身份 tell（官替占 `com.tencent.mm` 无此问题）。服务器侧是否据此处罚**未证**。
- **canary② 绑行为未做**（现 canary = 诱饵指纹 + 模块签名）；重签必触发 cert 绊线兜底（SSOT §4）。
