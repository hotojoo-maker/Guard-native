## ① 大白话

- **真锁 = 服务器发短命种子**；客户端只有「Ed25519 验签通过 + 租约有效 + SO 解密成功」全过，才拿得到真配方（registry）。任一失败 = **散沙**（乱码配方）→ 敏感隐藏链静默失效，但**不崩、不全开、不删用户数据**。
- **真锁的牙在「服务器种子解 registry」**（`isSensitiveConfigReady`）——`isVipAuthorized` 只是门（返回是/否），解密 registry 的翻译官才是锁。
- **最大的雷**：改钥匙派生 / 删明文 fallback 错一步 → 正版机密友隐藏**静默全挂、无报错**（F-31）。所以这条线每一步都要三端对账 + 装机回归。

## ③ SO 基线（现状）

- `libguardcore.so` 现有：`decrypt_config` + AES-GCM + encrypted registry + 派生 key（去明文常量）+ 证书绑定 + `registry_get_recipe` 取件口。
- 仍占位（**不是根锁**）：`nativeIsAuthorized()` / `nativeGetAuthState()`。
- `StateMachine.isVipAuthorized()` 已接 `EnvelopeStore.isAuthorizedNow()`（非 stub）。
- 官替 `android_8071` / 共存 `android_8071_coexist` 均 server seed 解 registry（v2 已合并同源 S_rel `7255096e` + 同 cert `e3e13a49`）。

## ④ 口径（诚实边界 · 对外能说什么 / 不能说什么）

- **能说**：商业授权最小闭环（客户端 pv `v1.6`）+ 当前发行线 prod_server_lock（server seed 解 registry）+ S4 Ed25519 防伪造信封 + S3b LeaseClock 授时/72h 离线强验，均装机 PASS。
- **禁止说**：「服务器真锁终局完成 / 授权无法破解」——删 Filter fallback、V3 发行线对齐、`EncryptedConfigLoader` 直接 risk-gating + 负向 L1、W_dev Batch3 均未收口。
- 客户端 APK 防不住反编译/改（预期威胁）；真锁靠**服务器种子 + 短命租约 + 设备绑定**，不靠藏在客户端。
